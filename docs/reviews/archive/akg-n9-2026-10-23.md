CR-85：贡献者名单与范围记录缺失。现已关联 endermiteDOTcn / PR #44，范围记录明确待上游合入，并区分贡献者真机验证与上游维护者复测。

CR-86：此前编译代码离线复现了旧 90% 在本轮 ACK + 50% 前被采纳。现每轮成功 ACK 独立计数，之前的结果均忽略；新增 4 项回归覆盖跨报告、同报告、缺 ACK 和跨轮超时。

CR-87：成功日志缺原始消息。传输层现返回电量及匹配消息，插件按电量变化记录其 HEX；测试核对消息与最终采纳的电量一致。

R1/R2：`AkgPlugin` 继承 `BatteryPluginBase`，默认开关关闭。唯一输出点同时核对开关和完整接口身份；只发已验证的 `0CD6` 查询，无配置写入、命令扫描或超时重发。

R3/R4/R5：探测使用基类线程池路径，轮询使用基类 I/O 锁。每次查询创建独立有界拼接器，句柄由基类持有和释放，没有新增线程、计时器、事件订阅或跨轮共享缓冲。失败有查询日志，异常由基类留痕；轮询沿用熔断和递增退避。

R6/R7/R8：注释指针指向 `hardware/akg.md`；纯 codec、拼接器和传输循环均被测试项目直接链接。真实 62 字节样本保留尾部旧消息，避免用裁剪样本掩盖旧缓存问题。

## 3. 修正与遗漏复核

普通中断输入读不到 N9 状态，新增 `HidD_GetInputReport` 控制读取入口。没有修改其它插件的输入路径。读取时严格使用有效片段长度，长度 0 时忽略整个旧缓存；查询前有限度排空队列，避免把历史电量当作本轮响应。

排空不能阻止尚未到达的结果；本轮 ACK 是采纳异步电量的必要条件。按消息顺序处理同一报告，不能因为报告后面有 ACK 就接受其前面的旧结果。成功日志只记录命中的电量消息，避免输出可能含配对信息的旧缓存。

## 4. 未能证实

主界面显示、长期轮询、电量下降、官方 App 对照、充电、关机和重新接收行为均未实测。Windows 单次 HID 控制调用使用原生超时，三秒窗口约束查询循环，不保证打断正在进行的系统调用。不能把本次成功推广到其它 AKG 型号或连接方式。

固定协议没有逐轮事务号，因此不能保证区分新 ACK 之后到达的旧结果；本次修复覆盖的是已复现的 ACK 前迟到结果。
